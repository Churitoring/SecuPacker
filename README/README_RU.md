## 1. Как использовать

Базовый процесс упаковки выглядит следующим образом.

**Шаг 1 — Установить плагин**

Поместите `Churitoring_SecuPacker.js` в папку `js/plugins/` вашего проекта и включите его в Менеджере плагинов RPG Maker. На этом этапе настройте параметры по своему усмотрению.

**Шаг 2 — Создать папку развёртывания**

В RPG Maker выберите **Файл > Развёртывание** и экспортируйте для платформы **Windows**.

**Шаг 3 — Запустить упаковку**

Запустите файл `.exe` игры в папке развёртывания. Экран прогресса упаковки появится автоматически. Не закрывайте окно в процессе. Даже если вы принудительно завершите процесс на полпути, игра, скорее всего, восстановится при следующем запуске — но лучше просто дождаться завершения.

**Шаг 4 — Распространить**

После завершения упаковки игра перезапустится автоматически. Затем вы можете напрямую передать эту папку развёртывания игрокам.

Примечание: если `Player Auto Update` установлен в `true`, игра закроется (вместо перезапуска) после диалогового окна подтверждения. Не перезапускайте игру в этот момент — это запустит попытку обновления со старой версией. Сначала загрузите упакованные файлы на GitHub Releases.

## 3. Справочник параметров

### 3-1. Общие настройки упаковки

**Packer Auto Update**

Перед началом упаковки плагин загружает последнюю версию с GitHub и перезаписывает `js/plugins/Churitoring_SecuPacker.js`. Если вы вносили какие-либо прямые изменения в этот файл, необходимо установить значение `false` — иначе ваши изменения будут отменяться при каждой упаковке. Если вы используете плагин без изменений, оставьте значение `true`.

**Game Binary Name**

Имя выходного упакованного файла. По умолчанию — `game.bin`, но здесь его можно переименовать. Допускается только имя файла — пути не поддерживаются. Рекомендуется выбрать менее предсказуемое имя. Расширение файла также можно изменить.

**Track Runtime Writes**

Во время тестирования, если другие плагины создают или изменяют файлы, эти пути записываются в `data/SecuPacker_RuntimeWrites.txt`. При упаковке файлы из этого списка исключаются из пакета и остаются на диске в исходном виде.

Если вы используете плагины, автоматически генерирующие файлы (например, файлы конфигурации), включите эту опцию. Рекомендуется оставить значение по умолчанию `true`, если нет особых причин для отключения.

Примечание: файлы, отслеживаемые этой опцией, исключаются из Player Auto Update и защиты SecuPacker.

**Strip Read-Only Attributes**

На финальном этапе очистки упаковки исходные файлы ресурсов удаляются. Если какие-либо файлы имеют атрибут «только чтение» (R), удаление завершится ошибкой. Если вы ведёте проект через Git или используете инструменты, автоматически помечающие файлы как «только чтение», установка значения `true` выполнит `attrib -R` перед удалением. Рекомендуется оставить значение по умолчанию `true`, если нет особых причин для отключения.

### 3-2. Настройки упаковки файлов

**File Split**

Вместо упаковки всех ресурсов в один файл, эта опция позволяет распределить их по нескольким упакованным файлам. Полезно для отделения ресурсов DLC от основной игры или для разбиения крупных проектов на несколько файлов. При установке значения `false` все записи в списке File Split List ниже также будут игнорироваться.

**File Split List**

Определяет правила, по которым файлы/папки распределяются по упакованным файлам. Каждая запись имеет две настройки:

- **Split Bin File**: Имя файла для этой группы. Должно отличаться от основного имени пакета, заданного в Game Binary Name. Напр.: `dlc.bin`, `bgm.bin`
- **Split Path Patterns**: Список путей для включения в этот файл. Указание папки, например `audio/bgm`, рекурсивно включит все файлы в ней. Также можно указать отдельный файл, например `audio/se/boss.ogg`.

**Packed File Exclusions**

Задаёт файлы или папки, которые следует исключить из упаковки и оставить на диске. Пути указываются относительно корня проекта с использованием прямых слешей (`/`). Напр.: `img/system/Loading.png`, `audio/bgm`

Добавьте сюда файлы, которые во время выполнения должны читаться непосредственно с диска. Файлы из этого списка исключаются из упаковки и не будут удалены.

Примечание: файлы из этого списка исключаются из Player Auto Update и защиты SecuPacker.

### 3-3. Настройки безопасности

**Block Launch Args Whitelist**

Если при запуске обнаружен аргумент строки URL-запроса или аргумент запуска NW.js, которого нет в этом списке, игра немедленно завершится. По умолчанию — пустой список, то есть все внешние аргументы блокируются. Добавьте в этот список аргументы, которые должны быть разрешены.

Эта проверка применяется только к упакованным дистрибутивным сборкам и не действует во время тестирования при разработке.

**Early Blob Resolve**

Переносит момент преобразования путей к файлам в Blob URL (внутри упакованного файла) на этап `Bitmap.load`. В большинстве случаев оставьте значение `true`.

Однако если вы используете плагин, который перехватывает `fs.readFile` или `XMLHttpRequest` напрямую для собственного дешифрования, установите значение `false` при возникновении конфликтов.

Установка значения `false` может снизить совместимость.

**Enable Cheat Detection**

Периодически сканирует хакерские инструменты, запущенные как фоновые процессы.

**Excluded Binary Hashes**

Имена (или части имён) бинарных файлов, которые исключаются при вычислении хэша отпечатка среды.

Причина, по которой `ffmpeg` включён по умолчанию, связана с лицензией FFmpeg (LGPL). LGPL требует, чтобы пользователи могли заменять бинарный файл собственной версией. Включение FFmpeg в хэш приведёт к его изменению при замене, что заблокирует запуск игры — поэтому он исключён по умолчанию для соответствия лицензии.

Оставьте значение по умолчанию, если нет особых причин для изменения.

Пример: `ffmpeg.dll` (исключает только ffmpeg.dll)  
Пример: `ffmpeg` (исключает и ffmpeg.dll, и ffmpegsumo.dll)

**Hash Exe Files**

При установке значения `true` файл `.exe` игры также включается в хэш отпечатка среды. Это предотвращает запуск упакованного файла с другим `.exe`. Важно: любые изменения `.exe` — например, замена иконки или изменение манифеста — должны быть выполнены **до** упаковки. Изменение `.exe` после упаковки изменит хэш и заблокирует запуск игры.

### 3-4. Дополнительные настройки

**Block Window Resize**

При установке значения `true` игроки не смогут изменять размер или разворачивать окно игры. Кнопка разворачивания может исчезнуть или перестать работать.

**Block F2 / F4 / F5 Key**

Блокирует соответственно отображение счётчика кадров (F2), переключение полноэкранного режима (F4) и перезагрузку игры (F5). Включите эти опции, если вы не хотите, чтобы игроки имели доступ к этим функциям в дистрибутивной сборке.

### 3-5. Настройки автообновления игрока

**Player Auto Update**

При установке значения `true` игра при запуске обращается к серверу релизов GitHub. Если доступна новая версия упакованного файла, она автоматически загружается и заменяет старую. Для использования этой функции необходимо также настроить `Player Auto Update URL` ниже.

При установке значения `true` игра закроется (вместо перезапуска) после завершения упаковки. Не перезапускайте игру в этот момент — это запустит попытку обновления со старой версией. Сначала загрузите упакованные файлы на GitHub Releases.

Если нужно проверить успешность упаковки, установите значение `false` перед тестированием.

**Player Auto Update URL**

URL репозитория GitHub, откуда будут загружаться обновления. Вводите в формате `https://github.com/имя_пользователя/репозиторий`. Приватные репозитории не поддерживаются.

Пример: `https://github.com/Churitoring/SecuPacker`

**Player Auto Update Tag**

Если оставить пустым, всегда обновляется до последнего релиза.

Если указан тег, обновление происходит из последнего релиза с этим тегом. Рекомендуется создать один репозиторий и назначать игровые теги релизам внутри него — так функция Player Auto Update сможет обслуживать несколько игр из одного репозитория.

Пример: `SecuPacker`

**Disable On No Internet / Disable On Fail**

Настраивает поведение при отсутствии интернета или недоступности сервера обновлений.

Если вы хотите, чтобы игра завершалась только при отсутствии интернета, но не планируете использовать функцию обновления, рекомендуется установить `Player Auto Update` в `true`, оставить `Player Auto Update URL` пустым, установить `Disable On No Internet` в `true` и `Disable On Fail` в `false`.

- Установка `Disable On No Internet` в `true` покажет предупреждение и закроет игру при отсутствии интернета.
- Установка `Disable On Fail` в `true` закроет игру, даже если сервер доступен, но файл не удаётся загрузить.

**Настройки экрана обновления (PAU Scene \*)**

Настраивает интерфейс, отображаемый в процессе автообновления.

*Текст*

- **PAU Scene Update Text**: Текст в области заголовка во время загрузки обновления. По умолчанию: `Updating...`
- **PAU Scene Complete Text**: Текст в области заголовка при успешном завершении обновления. По умолчанию: `Update complete!`
- **PAU Scene Failed Text**: Текст в области заголовка при сбое обновления. По умолчанию: `Update failed`

*Анимация*

- **PAU Scene Blink**: Применяет анимацию пульсирующей прозрачности к тексту заголовка. По умолчанию: `true`
- **PAU Scene Blink Speed**: Скорость цикла мигания. Чем выше значение, тем быстрее. При `0.050` — примерно один цикл каждые 2 секунды при 60 fps. Диапазон: `0.001` ~ `1.000`. По умолчанию: `0.050`

*Прогресс*

- **PAU Scene Show Progress**: Отображает прогресс загрузки (%) и размер (КБ) в области подтекста во время обновления. По умолчанию: `true`

*Фон*

- **PAU Scene BG Type**: Выбирает тип фона. `color` (однотонный цвет) / `image` / `video`. По умолчанию: `color`
- **PAU Scene BG Color**: CSS-код цвета для однотонного фона при типе `color`. По умолчанию: `#000000`
- **PAU Scene BG Image**: Файл фонового изображения при типе `image`. Выбирайте из папки `img/`.
- **PAU Scene BG Video**: Путь к видеофайлу при типе `video`. Вводится строкой. Напр.: `movies/bg.webm`
- **PAU Scene BG Fit**: Способ подгонки изображения или видео, когда соотношение сторон не совпадает с экраном. `cover` (обрезать для заполнения) / `contain` (letterbox, сохранять пропорции) / `fill` (растянуть). По умолчанию: `cover`
- **PAU Scene Video Loop**: Зацикливает фоновое видео. При `false` видео останавливается на последнем кадре. По умолчанию: `true`
- **PAU Scene Video Volume**: Громкость звука фонового видео. `0` (тихо) ~ `100`. По умолчанию: `100`

*Фоновая музыка*

- **PAU Scene BG Music**: Музыкальный файл для воспроизведения на экране обновления. Выбирайте из папки `audio/`. Можно использовать совместно с видеофоном.
- **PAU Scene BG Music Volume**: Громкость фоновой музыки. `0` (тихо) ~ `100`. По умолчанию: `80`
- **PAU Scene BG Music Loop**: Зацикливает фоновую музыку. При `false` воспроизводится один раз и останавливается. По умолчанию: `true`

*Стиль текста заголовка*

- **PAU Scene Title X Offset**: Горизонтальное смещение текста заголовка от центра экрана в пикселях. `0` = по центру. По умолчанию: `0`
- **PAU Scene Title Y Offset**: Вертикальное смещение текста заголовка от центра экрана в пикселях. Отрицательные значения смещают вверх. По умолчанию: `-30`
- **PAU Scene Title Size**: Размер шрифта текста заголовка в пикселях. По умолчанию: `36`
- **PAU Scene Title Color**: Цвет текста заголовка в формате CSS hex. По умолчанию: `#ffffff`
- **PAU Scene Title Outline Width**: Толщина обводки текста заголовка в пикселях. `0` = без обводки. По умолчанию: `0`
- **PAU Scene Title Outline Color**: Цвет обводки текста заголовка. Поддерживается CSS hex или формат `rgba()`. По умолчанию: `rgba(0,0,0,0.5)`

*Стиль подтекста*

Подтекст — это вторичная строка под заголовком, отображающая прогресс или статусные сообщения.

- **PAU Scene Sub X Offset**: Горизонтальное смещение подтекста от центра экрана в пикселях. По умолчанию: `0`
- **PAU Scene Sub Y Offset**: Вертикальное смещение подтекста от центра экрана в пикселях. По умолчанию: `30`
- **PAU Scene Sub Size**: Размер шрифта подтекста в пикселях. По умолчанию: `18`
- **PAU Scene Sub Color**: Цвет подтекста в формате CSS hex. По умолчанию: `#888888`
- **PAU Scene Sub Outline Width**: Толщина обводки подтекста в пикселях. `0` = без обводки. По умолчанию: `0`
- **PAU Scene Sub Outline Color**: Цвет обводки подтекста. Поддерживается CSS hex или формат `rgba()`. По умолчанию: `rgba(0,0,0,0.5)`

## 4. JavaScript API

Эти API можно вызывать напрямую из других плагинов или вызовов скриптов в качестве альтернативы командам плагина.

Прямой вызов API создаёт зависимость от SecuPacker. Чтобы избежать побочных эффектов при отключённом плагине, всегда проверяйте существование объекта перед вызовом.

**`SecuPacker.getVersion()`**

Возвращает строку версии SecuPacker.

```javascript
SecuPacker.getVersion();
```

**`SecuPacker.isPacked()`**

Возвращает `true`, если игра запущена в упакованном режиме, иначе `false`. Во время тестирования при разработке всегда возвращает `false`, поэтому это можно использовать для разветвления поведения в зависимости от того, является ли игра дистрибутивной сборкой.

```javascript
if (SecuPacker.isPacked()) {
    // Код, выполняемый только в дистрибутивных сборках
}
```

**`SecuPacker.isSplitAvailable(binName)`**

Возвращает `true`, если указанный разделённый упакованный файл существует и доступен. Полезно для проверки, установлен ли файл DLC.

```javascript
SecuPacker.isSplitAvailable("dlc.bin"); // true или false
```

**`SecuPacker.isPlayerAutoUpdateReady()`**

Возвращает `true`, если Player Auto Update включён и настроен URL.

```javascript
SecuPacker.isPlayerAutoUpdateReady(); // true или false
```

## 5. Команды плагина

Команды плагина, доступные в MZ.

**GetVersion** — Сохраняет строку версии SecuPacker в переменную игры.

**IsPacked** — Сохраняет `true`, если игра упакована, иначе `false`, в переменную игры. Используйте для ветвления внутриигрового поведения в зависимости от того, является ли сборка дистрибутивной.

**IsSplitAvailable** — Проверяет, существует ли указанный разделённый упакованный файл и доступен ли он, и сохраняет результат в переменную игры. Полезно для проверки наличия файла DLC.

**IsPlayerAutoUpdateReady** — Сохраняет `true` в переменную игры, если Player Auto Update включён и настроен URL.
